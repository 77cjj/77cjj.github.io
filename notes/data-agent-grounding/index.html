参考原文OpenAI · Inside OpenAI’s in-house data agent ↗以下是独立中文札记，并非原文翻译。来源观点与个人推论分开展示。

问题从哪里来

“查一下上季度的使用情况”看似是 SQL 任务，真正困难的可能是指标定义、数据表选择、权限范围和结果解释。OpenAI 介绍内部数据 Agent 时，把数据上下文、执行和评测放在同一条链路上。

原文给出的线索

  1. 让 Agent 看到表结构还不够；字段业务含义、常见连接关系和指标口径同样影响答案。
  2. 查询结果应能追溯到数据源和运行过程，避免用自然语言的流畅度掩盖错误口径。
  3. 内部产品案例说明一种实践方向，不代表相同架构在别的组织会自动奏效。

我的理解 · 可以怎么试

我会先做十个由业务方确认答案的数据问题，记录期望表、过滤条件和结果口径。每次改 Agent，先查这些答案是否仍一致。
