评测与可靠性 / 原文解读

长任务的关键，是让下一轮知道上一轮做到哪了.

把任务进度留在可检查的文件与测试里。

Dream · 2026.09短篇阅读札记
参考原文Anthropic · Effective harnesses for long-running agents ↗以下是独立中文札记，并非原文翻译。来源观点与个人推论分开展示。

问题从哪里来

一个 Agent 运行数小时，未必能靠不断压缩对话保持方向。Anthropic 在长时编码实验中，让初始化阶段准备环境和任务清单，后续每轮只推进一小段，并留下给下一轮看的产物。

原文给出的线索

  1. 新会话如果不知道当前状态，容易重做旧工作、误判完成度，或者试图一次解决全部需求。
  2. 进度记录需要落到可验证的东西：已改文件、测试结果、未完成项和下一步，而非只写“完成了很多”。
  3. 这是特定编码场景的工程方案，不是所有长任务都必须采用同样的 Agent 分工。

我的理解 · 可以怎么试

我的最小交接包会包含任务目标、最新可运行状态、失败测试、具体下一步。用新会话能否接着做来检验它，而不是用笔记长度衡量。
