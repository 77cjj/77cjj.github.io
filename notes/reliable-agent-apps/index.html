AI AGENTS · 2026.09 · 约 3 分钟

从能运行的 Demo，
到可靠的 AI Agent 应用.

模型能调用工具，只是一个起点。真正值得投入的，是它遇到不确定性、失败和真实用户时，仍然能清楚地工作。

NOTE 001
BUILD / TEST / REFINE

先定义它要完成什么

一个 Agent 演示很容易显得聪明：给它一段任务描述、几个工具，再展示一次顺利的运行。但应用面对的是重复而不整齐的真实输入。我的兴趣不只在于让模型“能做”，还在于把任务边界、成功标准和需要人接手的时刻说清楚。

因此，开始开发前，我更愿意先问：用户究竟想得到什么结果？哪些步骤必须可追溯？哪些行为只能建议、不能自动执行？这些问题通常比选择某个框架更早决定产品是否可靠。

把失败路径也设计进去

检索可能找不到证据，工具可能超时，外部服务可能不可用，模型也可能误解含糊的指令。可靠的系统不该把这些情况藏在一段流畅的回答里，而应该让错误可见、允许重试，并在必要时停下来请人确认。

对于有真实后果的操作，我会把“生成建议”与“执行动作”分开考虑：先展示依据和影响范围，再由用户决定是否继续。这样的边界会让系统慢一点，却也更容易信任。

持续检验，而不是只看一次成功

一个好的测试集应包含正常案例，也包含信息缺失、互相矛盾、工具失败和超出权限的请求。观察的不只是最终回答，还包括它引用了什么、调用了哪些工具、何时承认不知道，以及失败后能否恢复。

这也是我想在这里长期记录的主题：把 AI Agent 从令人印象深刻的演示，逐步打磨成可以解释、可以维护、也知道自己边界的应用。
