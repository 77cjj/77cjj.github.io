参考原文Anthropic · How we built our multi-agent research system ↗以下是独立中文札记，并非原文翻译。来源观点与个人推论分开展示。

问题从哪里来

研究问题常会在搜索中改变方向：一条线索通向新的来源，另一条线索需要反证。Anthropic 的 Research 系统用主 Agent 分派独立探索，再汇总发现；文章也坦率写了协调成本和 token 消耗。

原文给出的线索

  1. 子任务需要独立目标、输出格式、工具范围与边界，否则多个 Agent 容易重复搜索或留下空白。
  2. 并行的价值来自广度与独立上下文；如果步骤彼此强依赖，协调成本可能超过收益。
  3. 源文中的性能数字来自 Anthropic 内部评测，不能直接推广到任何项目或模型组合。

我的理解 · 可以怎么试

我的试验门槛是：先证明任务能拆成至少两个真正独立的方向，再比较单 Agent 与分工版本的覆盖率、重复率和总成本。
