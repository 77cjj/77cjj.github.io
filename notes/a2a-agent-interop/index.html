Agent 之间如何协作：A2A 解决的不是工具调用.

跨服务委派与单个 Agent 使用工具，是两种不同的接口。

Dream · 2026.09短篇阅读札记
参考原文Google Developers Blog · Announcing the Agent2Agent Protocol ↗以下是独立中文札记，并非原文翻译。来源观点与个人推论分开展示。

问题从哪里来

当两个 Agent 属于不同团队或平台时，一个 Agent 很难直接知道对方内部用了哪些工具。Google 推出的 A2A 协议把重点放在发现能力、交换任务和结果，让协作双方保留各自的实现。

原文给出的线索

  1. 跨系统协作需要明确能力声明、任务状态和消息内容，而不只是把请求转发给另一个模型。
  2. 认证授权和用户体验同样重要：发起方应知道对方能做什么、做到哪一步、是否需要进一步输入。
  3. A2A 面向 Agent 之间的互操作；MCP 更常用于 Agent 与工具/数据源连接，两者不必互相替代。

我的理解 · 可以怎么试

只有当任务真的跨越独立服务边界时，我才会引入 Agent 间协议。单一产品内部的两个步骤，用普通函数或工作流可能更清晰。
