把该确定的步骤交给代码，把判断留给 Agent.

什么时候用工作流，而不是放任模型决定一切。

Dream · 2026.09短篇阅读札记
参考原文Microsoft Learn · Agent Framework Workflows ↗以下是独立中文札记，并非原文翻译。来源观点与个人推论分开展示。

问题从哪里来

一份文档必须先起草、再审查、最后由人批准，这个顺序不应靠模型临场发挥。Microsoft 的工作流文档把 Agent 应用看作从自主到确定性的一条光谱：流程由代码约束，某些节点才交给模型推理。

原文给出的线索

  1. 若步骤顺序、审批点或恢复位置已知，应显式定义工作流，而不是希望模型每次都记住。
  2. Agent 可以在工作流节点内负责需要判断的局部问题；普通代码负责确定性的校验与状态转换。
  3. 检查点让部分失败后从已完成状态继续，但这需要把状态设计成可恢复，而不是只保存聊天记录。

我的理解 · 可以怎么试

我会先把流程画成状态图，标注谁有权决定每条边：代码、模型还是人。只有模型真正需要判断的边，才给它选择权。
