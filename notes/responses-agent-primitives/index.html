问题从哪里来

OpenAI 介绍 Responses API、内置工具与 Agents SDK 时，强调的不只是多一个调用入口，而是把工具使用、工作流编排和执行轨迹连起来。对应用开发者来说，关键问题是一次任务经历了哪些决定。

原文给出的线索

  1. 网页搜索、文件搜索和计算机操作解决不同的取证与行动问题，不能因为都叫“工具”就混用。
  2. 编排层应能看见模型请求、工具返回、停止条件与错误；否则线上问题只能靠猜。
  3. 这篇是 2025 年的产品发布说明，具体 API 形态会变化，设计思路需要与最新文档分开看。

我的理解 · 可以怎么试

选框架之前，我会画出一条完整轨迹：模型决定什么、代码执行什么、用户确认什么。只要其中一段不可观察，先补观测再加自主性。
